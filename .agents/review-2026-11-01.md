## 1. 高优先级问题（数据丢失 / 卡顿 / 第一印象）

### P1-1 启动即持续 A4 长音（诊断遗留，默认开启）

- 证据：`crates/glitcherz-app/src/main.rs:58` `auto_play_note: (!args.no_autoplay).then_some(args.note)`；
  `main.rs:82` `no_autoplay: false`；`ui/src/lib.rs:1587` 直接发 `NoteEvent::On { note, velocity: 1.0 }`，**无 Off**。
- 后果：双击图标 → 立即持续 A4 长鸣，直到关闭窗口。这是 roadmap step 3 的验声遗留。
- 修法：语义反转 —— 默认静音，`--autoplay` 显式开启（诊断/冒烟用），`--no-autoplay` 保留为兼容别名。

### P1-2 保存非原子 + 无备份

- 证据：`crates/glitcherz-model/src/file.rs:72` `std::fs::write(path, text)?`。
- 后果：写入过程中崩溃/断电 → 工程文件截断，undo 栈随进程消失。
- 修法：先写 `<name>.glz.tmp` 再 `fs::rename`（同目录 rename 在 Win32/POSIX 都原子）；成功后把旧文件留一份 `<name>.glz.bak`。

### P1-3 不拒绝"未来版本"文件

- 证据：`file.rs:95-118` —— 只做 `if version < N { migrate }`，`version > PROJECT_VERSION` 直接放行。
- 后果：旧版本打开新版本工程 → serde 丢弃未知字段 → `validate` 通过 → 再保存**静默丢数据**。
- 修法：`if version > PROJECT_VERSION { 明确报错 }`（错误文案带两个版本号）。

### P1-4 参数拖动每帧深拷贝整个 Project

- 证据：`crates/glitcherz-command/src/lib.rs:166` `project_mut()` = `Arc::make_mut`；
  AGENTS.md 约定参数手势为「每帧 `begin_param_edit` → `project_mut` → `commit_param_edit`」。
- 机理：`begin_param_edit` 持有 doc 的 `Arc` 克隆 → `make_mut` 发现 refcount ≥ 2 → **每帧整体深拷贝**。
  全仓该模式共 **62 处**（全部在 `ui/src/lib.rs`）。
- 量级：普通工程（约 2k 音符 / 50 KB）≈ 3 MB/s memcpy，无感；密集导入工程（2 万+ 音符）会明显掉帧。
- 附带问题：undo 栈上限是**条数**（`DEFAULT_HISTORY_LIMIT = 200`），没有字节上限
  → 大工程 200 步快照可吃掉 GB 级内存。
- 拆两条做：
  - **S1-3a（本次做）**：undo 栈加字节预算，按估算体积裁剪。小改、无行为变化。
  - **S1-3b（S2）**：新增真正的手势 API（快照只在首帧取、`project_mut` 只在值变化时写、
    release 提交），替换 62 处调用点。需要先想清楚"拖动期 UI 读到的是引擎值还是文档值"。

### P1-5 每次 undo/redo 全量重建引擎

- 证据：`ui/src/lib.rs:2624` `undo()` → `apply_document()`（`:1613`）→ 删光 `node_map` 全部节点 →
  按文档重装；`install_node`（`1838-2285`，447 行）对每个插件节点走 `ClapInstance::spawn_rt` /
  `Vst3Instance::spawn_rt` + `guard.load_state`（`2043-2133` 一带）。
- 后果：撤销一步"重排轨道"= 所有 CLAP/VST3 实例销毁重建 + 状态回灌 → 数百毫秒卡顿、期间静音。
  插件越多越明显（Dexed 级插件单次实例化即为可感量级）。
- 修法：`sync_document(prev, next)` diff 同步。原语已齐（`replace_node` / `insert_node_between` /
  `connect_nodes` / `remove_node`），只需按 node_id 求差集 + 连线差集。

### P1-6 无音频设备 / 采样率 / 缓冲区设置，无掉线恢复

- 证据：`engine/src/engine.rs:88-141` 只取 `default_output_device()`；UI 侧零设备选项
  （全仓 `default_output_device` 仅此一处调用）；`build_output_stream` 的 error 回调只 `log::error!`。
- 后果：Windows 用户无法选 ASIO（AGENTS.md 已提"建议装 ASIO SDK"）；无法降 latency；设备热插拔后静默无声。
- 修法：Preferences 面板（device / sample rate / buffer）+ `AudioEngine::start_with(DeviceConfig)` +
  错误回调上报原子位，UI 提示并提供"重启音频引擎"。

## 2. 功能缺口（对照"能用来做歌"的基线）

| 缺口 | 现状（证据） | 影响 |
| :--- | :--- | :--- |
| **录音** | 全仓无 `build_input_stream`，依赖无 `midir` | 最大缺口：只能画 MIDI、只能导入 wav |
| **节拍器** | 零实现 | 录音的前置，跟拍也需要 |
| **PDC（插件延迟补偿）** | `realtime/processor.rs:38` `latency_samples()` 是死钩子，注释写"plugin delay compensation will consume it"，无调用方 | 有 latency 的插件并联 → 相位糊 |
| **自动保存 / 崩溃恢复** | 无 | 与 P1-2 叠加，一次崩溃即全丢 |
| **Undo 历史面板** | `Session::undo_history()` / `undo_label()` 已实现但**零 UI 调用**（死 API） | 后期混音无法回溯 |
| **导出规格** | `ui/src/export_audio.rs:135-141` 固定 16-bit stereo wav，采样率跟随设备 | 无法 24-bit 交付、无 stems |
| **工程可移植** | `path: String` 存**绝对路径**（`model/lib.rs:1296/1704`），无缺失媒体重定位 | 换机/分享 → 静音 |
| **中文支持** | 未加载任何 CJK 字体（全仓无 `FontDefinitions`）；AGENTS.md 明写"egui 默认字体无 CJK 字形" | 中文轨名/片段名显示为豆腐块 |
| **自动化表达力** | 每 clip `MAX_CURVE_POINTS = 64`；一曲线只能一个目标（plan 已列 C5）；CC 块级量化 | 画不出细 sweeps；LFO 扇出做不到 |
| **固定容量** | 16 MIDI 轨 / 8 audio 轨 / 16 控制轨 / 64 节点 / 256 连线 | RT 设计取舍合理，但 16 轨偏低 |

  - 顺带去掉保存路径上的一次 `Project` 全量深拷贝：新增 `ProjectFileRef<'a>`（只 derive

- 测试（`file.rs`）：
  - `a_save_is_atomic_and_keeps_the_previous_revision`（无残留 `.tmp`、首次保存无 `.bak`、
    第二次保存的 `.bak` 是旧版本内容、当前文件是新内容）
  - `a_file_from_a_newer_build_is_rejected`（v+1 报 `NewerVersion`，当前版本仍可读）

### S1-3a undo 栈按字节预算裁剪 ✅

- `model/lib.rs`：新增 `Project::approx_bytes()`（`Vec` 按 `len * size_of::<T>()` 计价，
  忽略不会长大的标量载荷）+ 私有 `NodeDoc::payload_bytes()` / `VoiceSpec::payload_bytes()`
  （插件 `state` blob、drum slot 路径、音色库路径）。
- `command/lib.rs`：
  - `DEFAULT_HISTORY_BYTES = 256 MiB`，`HistoryEntry.bytes` 缓存入栈时的估算值。
  - 新增 `history_bytes()` / `history_byte_limit()` / `set_history_byte_limit()`。
  - `push_undo` / `execute` 统一走 `record_history()`；`clear_redo()` 同步扣减字节。
  - `trim_history()`：先按条数裁，再按字节裁（**先丢 redo 尾部、再丢 undo 最旧**），
    永远保留 ≥1 步（单步就超预算时也不清空，否则重工程等于没有 undo）。
  - `undo()` / `redo()` 在栈间搬运时同步维护字节数（弹出的快照变成活文档 → 不再计入）。
- 测试（`command/tests/transactional.rs`）：
  - `history_is_bounded_by_memory_not_just_step_count`（预算 = 2.5 个快照 → 只留 2 步）
  - `one_oversized_step_still_leaves_undo_usable`（预算 = 1 字节 → 仍有 1 步可撤销）
- **过程中修掉一个真 bug**：初版 `take_oldest_undo/redo` 直接用 `drain(..1)`，在**空栈**上
  会越界 panic（预算裁剪第一次就会走到）。改为 `drain(..len.min(1))`。由上述测试捕获。
