# 时间轴缩放：只留滚轮与键盘

> ID: F-047 · 域: UI / EDIT
> 状态：**已实施**（2026-11-17）
> 关联：`timeline.md`（T3 视图导航）、`snap-granularity.md`（同一工具栏的吸附下拉）、`clip-data-panel.md`（F-046 D3：分栏只切分工具栏之下的空间）

## 1. 问题

### 1.1 一个 `-`/`+` 对要管两个轴

时间轴的水平刻度是 `px_per_bar`，行高是 `row_zoom`。工具栏的 `-`/`+` 只改前者，而 `Ctrl+Alt+滚轮` 改后者——同一个视觉组里只有一半的缩放在按钮上，另一半只存在于手势里。补成两对按钮（`H -/+`、`V -/+`）是四个按钮，对一个"每首歌调两次"的控件来说太重。

### 1.2 标题没有信息量

那行的 `Arrangement` 是分组标题，整个视图就是 arrangement；它唯一的作用是引出后面的 `-`/`+`，控件没了它也就没有指代对象。叫 `Zoom` 也只是给一对按钮贴名字。

### 1.3 按钮与滚轮是两套语义

| 入口 | 锚点 | 步长 |
| :--- | :--- | :--- |
| `Ctrl+滚轮` | 指针下的 tick | 连续（`zoom_delta`） |
| `-`/`+` | 无（只改数值，视图不补偿） | 固定 1.3× |

按钮那条路径没有偏移补偿：在水平滚动过的视图里点 `+`，内容会整体向右跑，正在看的位置漂掉。这不是"少一个功能"，是同一状态的两套更新方式里有一套是错的。

## 2. 决策

| # | 决策 | 内容 |
| :--- | :--- | :--- |
| D1 | **删掉 `-`/`+` 与那行标题** | 工具栏不再有缩放控件，也不再保留 `Arrangement` / `Zoom` 之类的分组标题——没有控件就没有可命名的组。吸附下拉成为工具栏最左控件 |
| D2 | **两轴都留在滚轮** | `Ctrl+滚轮` = 水平（锚在指针）；`Ctrl+Alt+滚轮` = 行高。两者已实现，不动 |
| D3 | **键盘补水平固定档** | `-` / `=` 按 1.3× 一档；`+`（多数布局的 `Shift+=`）与数字小键盘同义。行高不做键盘档：它是一次性"看看有几轨"的动作，滚轮够用，键位留给更常用的命令 |
| D4 | **键盘锚在视口中心** | 键盘没有"这里"。锚在指针会让同一个键随悬停位置缩放不同地方；视口中心可预测，也符合"缩放到正在看的地方" |
| D5 | **焦点门控** | 与 `G`/`T`/`K` 同级：时间轴持有键盘焦点、无模态、不在文本框里才响应。`-` / `=` 因此不会在卷帘或文本输入里误触 |
| D6 | **抽公共算法** | `TimelineState::zoom_time_axis` 统一"改缩放 + 返回保持锚点 tick 不动的滚动偏移"；滚轮与键盘共用一份锚点数学，避免两处漂移（1.3 的教训） |
| D7 | **不绑 `Ctrl+` / `Ctrl+-`** | eframe 的 `zoom_with_keyboard` 把这两个组合留给整个 UI 的 DPI 缩放，抢会打架 |

## 3. 实现

- `timeline.rs`：新增 `TimelineState::zoom_time_axis(ctx, scroll_id, base_bar_ticks, anchor, factor) -> Option<Vec2>`；滚轮分支从内联算式改为调用它，键盘分支新增。
- 锚点几何：`rows_viewport_min: Pos2` → `rows_viewport: Option<Rect>`。键盘需要视口**中心**，一个 `min` 点不够；同时也保留了滚轮的 `min`。
- 工具栏：删 `ui.strong("Arrangement")` + `-` / `+` 两个按钮 + 其后的 `separator()`。
- 静态提示行尾部：`Ctrl+wheel or -/= zoom · Ctrl+Alt+wheel height · MMB pan`。

## 4. 验收

1. 工具栏没有 `-`/`+`，也不再出现 `Arrangement`；吸附下拉是最左控件，其余按钮位置与行为不变。
2. `Ctrl+滚轮`：指针下的 tick 保持不动（与改造前逐像素一致）。
3. `Ctrl+Alt+滚轮`：行高变化，水平刻度不变。
4. `-` / `=`：以视口中心为锚，一档 1.3×；连按不漂移；到上下限后数值不变、不报错。
5. `-` / `=` 在时间轴未持有焦点、模态进行中、文本框编辑中都不生效（退格与普通字符不受影响）。
6. 键盘缩放后，行列位置、标尺、clip 命中都不需要下一帧就恢复正确（缩放与偏移补偿同帧生效）。

## 5. 不做

- `Zoom` 弹出面板（两轴各一对 `-`/`+`、重置、fit）——一个弹窗换两个按钮，交互更重。
- 行高的键盘档位、fit-to-content、缩放到选区。
- 触摸双指捏合：`zoom_delta_2d` 已按两轴解算，本次不动。

## 6. 风险

| 风险 | 说明 | 缓解 |
| :--- | :--- | :--- |
| 发现性下降 | 没有可见控件，新用户不知道能缩放 | 静态提示行 + `manual.md` + `shortcuts.md` 三处；滚轮缩放是 DAW 通用手势 |
| 锚点语义不一致 | 键盘锚视口中心，滚轮锚指针 | 两者场景不同（有/无指针），文档写明；不接受"键盘也用上次指针位置"——那是隐藏状态 |
| 键位冲突 | `-`/`=` 在文本框里是普通输入 | `text_edit_focused()` 守卫（D5） |
