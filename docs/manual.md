# GlitcherZ 用户手册

界面文案是英文的，正文保留原文以便对照屏幕。

## 界面

窗口从上到下是四条：

| 区域 | 内容 |
| :--- | :--- |
| 走带栏 | `File` / `Edit` 菜单；`▶` / `⏸`、`⏹`、`⏮`、`⏭`；`🔁` 循环、上/下一个标记；节拍器（梯形摆锤图标）；`⏺` 录音与录音选项；BPM 输入框与拍号输入（每小节 1–12 拍、每拍 1/2–1/16；导入的超范围拍号只读显示）；右侧 `Master` 推子、立体声电平表和 panic 按钮。按钮全是图标，名称和快捷键在悬停提示里 |
| 标签栏 | `Timeline` / `Edit` / `Patch` / `Inspector` |
| 主区域 | 当前标签的内容 |
| 状态栏 | 当前编辑目标、音符名、键盘映射、`Pos 小节.拍`、最近一条消息（失败是红色） |

标签顺序按动手的顺序排：`Timeline`（编曲）→ `Edit`（卷帘 / 曲线）→ `Patch`（节点图）
→ `Inspector`（选中节点的参数）。启动时默认停在 `Timeline`——那是 DAW 的主视图，也是第一个标签。
切换可以点标签，也可以按 `Tab` / `Shift+Tab` 循环，或用 `Alt+1` .. `Alt+4` 直接跳
（编号就是上面的顺序）。`Tab` 被视图切换独占，代价是 egui 的控件焦点遍历不再生效——
`File` / `Edit` 菜单只能用鼠标点。

`Edit` 菜单只有四项：`Undo`（`Ctrl+Z`）、`Redo`（`Ctrl+Y`）、`Undo History…`、
`Preferences…`。`Undo History…` 是浮窗，最新在上，当前行高亮，灰行可以 redo，点一行就跳到那一步之后。

## 工程

| 操作 | 位置 |
| :--- | :--- |
| 新建 | `File ▸ New`（`Ctrl+N`） |
| 打开 | `File ▸ Open…`（`Ctrl+O`）、`File ▸ Open Recent` |
| 保存 | `File ▸ Save`（`Ctrl+S`） |
| 另存为 | `File ▸ Save As…`（`Ctrl+Shift+S`） |
| 导入 MIDI | `File ▸ Import MIDI…`（`.mid` / `.midi` / `.smf`） |
| 导出 MIDI | `File ▸ Export MIDI…` |
| 导出音频 | `File ▸ Export Audio…` |
| 收集媒体 | `File ▸ Collect Media Files…` |
| 重定位缺失媒体 | `File ▸ Relocate Missing Media…` |

标题栏出现 `*` 表示有未保存改动。新建 / 打开 / 关窗时如果文档是脏的，会先弹
`Unsaved changes`（`Save` / `Discard changes` / `Cancel`）。

保存是崩溃安全的：先写 `.tmp` 再原子重命名，上一版留成 `.bak`。细节见
[project-files.md](project-files.md)。

打开工程时如果有采样 / SoundFont / 音频文件找不到了，会弹一个缺失列表，可以
`Locate Folder…` 选目录按文件名重定位，或 `Continue without them` 先继续。

## 轨道

三种轨道，各自独立计数，都可以在 `Timeline` 工具栏或 `Patch` 的 `Timeline` 节点上加 / 减：

| 轨道 | 上限 | 用途 |
| :--- | ---: | :--- |
| MIDI | 16 | 音符片段，送进乐器节点 |
| Curve（控制轨） | 16 | 自动化曲线片段，连到某个参数 |
| Audio | 8 | 直接放音频文件片段 |

单轨最多 32 个片段，编曲总长 256 小节（4/4 下）。

采样播放器 / 鼓机槽位 / 音频片段都读这些格式：WAV、FLAC、MP3、Ogg Vorbis（`.ogg`）、
M4A（AAC-LC）、AIFF —— 文件选择框的 `Audio` 过滤器就是这份清单。WAV 走原生解码，
其余格式在载入时一次性解码成内存里的立体声采样；播放按文件自身采样率换算，不做重采样。
导出与录音**仍然只写 WAV**。Ogg 指 Vorbis（不含 Opus），超过 2 声道的文件会被拒绝。

- 点行首选中轨道；`Alt` + 点击只选这一个，框选可以多选。
- 轨道名：右键行首的轨道名 → 就地编辑，`Enter` 确认、`Esc` 取消，清空则回落 `Track N`。
  `Patch` 视图的 `Timeline` 节点每个输出口旁也显示当前轨道名，同样可以右键改名；
  两处实时同步，改动只记一步 undo。
- 片段名：`F2` 或 `Alt` + 双击片段。
- 行首的小圆点可以上下拖动调整轨道顺序。
- 静音、独奏、音量、声像在 `Mixer` 节点的通道条上，不在行首。

视图操作：`Ctrl` + 滚轮水平缩放，`Ctrl` + `Alt` + 滚轮改行高，中键拖拽平移。

## 编曲时间轴

| 操作 | 结果 |
| :--- | :--- |
| 拖动片段主体 | 移动（吸附到小节） |
| 拖动片段右边缘 | 扩展/缩短片段长度；平铺片段的周期随长度缩放 |
| 拖动片段左边缘 | 裁剪片段头部（起点右移、内容位置不动）；单周期 MIDI / 曲线片段会真正裁掉开头，跨界音符保留尾巴；平铺片段只缩短容器、保持重复相位 |
| 双击空轨道 | 插入一小节片段并自动选中（可直接 G / T 操作）；音频轨会弹出音频文件选择框 |
| 双击片段 | 进 `Edit` 标签（MIDI → 钢琴卷帘，Curve → 曲线编辑器） |
| `Alt` + 双击片段 / `F2` | 原地重命名片段 |
| `Ctrl` + 中键单击片段 | 临时静音 / 取消静音（片段淡显并带 `M` 角标，位置、长度、内容都不变） |
| 右键片段 | 删除 |
| 标尺点击 / 拖动 | 定位播放头 |
| 标尺 `Ctrl` + 拖动 | 画 song loop；拖 loop 边缘可改范围 |
| 标尺右键 | 加标记；在标记旗上右键删除 |
| 右键行首轨道名 | 重命名轨道 |
| 拖行首圆点 | 调整轨道顺序 |
| 轨道空白处单击 | 让时间轴拿到键盘焦点（`G` / `T` / `K` 等命令的前提） |

时间轴的模态命令（需要焦点，工具栏会显示当前状态）：

| 键 | 作用 |
| :--- | :--- |
| `G` | 抓取移动选区；`X` 锁定纯时间轴、`Y` 锁定纯轨道行；混合类型选区一起移动，各组沿自己的行滑动 |
| `Shift+D` | 复制选区并进入抓取；同样支持 `X` / `Y`；支持混合类型选区 |
| `T` | 扩展/缩短选区尾边；模态中按 `S` 切到首边 |
| `Shift+T`（`Alt+T` 备用） | 平铺：向右拖动增加整段重复、往左减少；已平铺片段再按一次 = 调整重复份数；1 小节的片段也能平铺 |
| `K` | 刀片：点一次切一刀（按小节吸附），`Esc` / 右键取消 |
| `Delete` | 删除选中片段 |
| `Ctrl+G` / `Ctrl+Shift+G` | 编组 / 解组选中片段 |
| `H` / `Alt+H` | 静音选中片段 / 恢复整个编曲里的静音片段 |
| `Esc` / 右键 | 取消当前模态 |

模态命令按下即生效、跟随鼠标，左键落下，右键或 `Esc` 放弃（Blender 式，卷帘里同名同义）。

工具栏上的 `Grab` / `Stretch` / `Tile` / `Knife` 是同一批命令的按钮形式（悬停显示快捷键），
它们是**一次性**的：点下去只是把工具「上膛」（armed，按钮描边），用掉一次、被另一个工具顶掉，
或者 `Esc` / 右键取消就结束；再点一次同一个按钮也是取消。时间轴没有画笔模式，所以在那里
永远只有这一组动作按钮——建片段是双击空轨道，不是「切到某个模式」。从按钮上膛时，抓取点会
推迟到指针进入轨道区的那一帧，片段不会先蹦一下。

片段的**临时静音**（clip mute）是非破坏性的：片段留在原位、长度与内容一概不变，只是不发声
（Curve 片段则是不投递自动化，目标保持最后的值）。静音的片段整块淡显、右上角带 `M` 角标，
仍然可以选中、拖动、改长度和进 `Edit` 编辑；编曲长度也不因静音而缩短。轨道级的静音 / 独奏
仍归 `Mixer` 通道条，两者互不影响。

## 编辑视图

`Edit` 标签跟随时间轴选区：选中 MIDI 片段就是钢琴卷帘，选中 Curve 片段就是曲线编辑器，
音频片段没有编辑器（音频轨直接用片段本身的裁剪窗口）。

在本标签按 `Play` / `Space` 是**试听当前片段**：从片段起点播到它的结尾（含平铺重复的整段），
自动停止并回到起点。试听中再按 `Play` / `Space` 暂停；切到别的标签会自动停止试听，
回到 `Timeline` 后 `Play` 恢复整曲播放。

卷帘上方是一条独立的 clip 标尺（ruler）：小节号按当前拍号分段绘制（与 `Timeline` 一致），
覆盖整个片段跨度（含平铺重复）；左键点击 / 拖动标尺移动播放头（小节吸附，按住 `Ctrl` 关闭吸附）。
停止时播放头仍静态显示；平铺区只在标尺上可见，主卷帘仍只展开一个内容周期。

### 钢琴卷帘

工具栏分两组，语义不同、不能互换：

| 组 | 内容 | 行为 |
| :--- | :--- | :--- |
| 模式 | `[Select]` `[Draw]` | 互斥、持久，当前模式填充；点当前模式不会关掉它（`D` 也能切换） |
| 动作 | `Grab` `G` · `Scale` `S` · `Stretch` `T` · `Knife` `K` | 一次性，armed 时描边；用掉 / 取消 / 被顶掉即结束 |

两种常驻模式：

| 模式 | 进入 | 行为 |
| :--- | :--- | :--- |
| `Select` | 默认 | 左键拖拽 = 移动选中音符 / 拖边缘裁剪 / 空白处框选 |
| `Draw` | 按 `D` 切换；`Esc` 也能退出 | 在空白处拖拽 = 画音符 |

从工具栏按钮上膛（arm）的动作，抓取点会推迟到指针进入网格的那一帧：按钮本身在网格外面，
用它的位置当零点会让选区在指针移动途中先跳一下。

命令与手势：

| 操作 | 结果 |
| :--- | :--- |
| 双击空白 | 插入一个默认长度的音符 |
| 拖音符主体 / 拖边缘 | 移动 / 裁剪（不限次数的手势形式） |
| `Ctrl` + 拖音符 | 拖动 / 裁剪时不吸附（临时关闭吸附） |
| `Shift` / `Ctrl` + 点击 | 加选 / 切换选择 |
| 右键音符 | 删除 |
| 方向键 | 上下一律、`Shift` 上下八度、左右一格 |
| 滚轮 | 上下滚动音高；`Shift` + 滚轮沿时间轴滚动 |
| `Ctrl` + 滚轮 / `Ctrl` + `Alt` + 滚轮 | 时间轴缩放 / 音高缩放 |
| 中键拖拽 | 平移 |
| `G` / `S` / `T` / `K` / `Shift+D` | 抓取 / 缩放 / 拉伸（`T` 后按 `S` 切首边）/ 刀片 / 复制 |
| `X` / `Y` | 模态中锁时间轴 / 锁音高 |
| `Esc` / 右键 | 取消模态 |

`Notes` 菜单（工具栏）收拢 MIDI 命令族，均作用于选区；没有选区时作用于整个片段。
菜单顶部可调 `strength`（量化强度 0–100%）与 `gap`（连奏 / 粘合允许的空隙，单位 tick）：

| 命令 | 快捷键 | 作用 |
| :--- | :--- | :--- |
| `Quantize` | `Q` | 音符起点按当前网格与 `strength` 吸附 |
| `Legato` | `L` | 把每个音符延长到下一个音符起点前 `gap`（最后一个保持不变） |
| `Glue` | `Shift+G` | 合并间距 ≤ `gap` 的同音高音符为一条 |
| `Remove Overlap` | `R` | 在后一个同音高音符起点处截断前一个（去重叠） |
| `Transpose` | — | 整体移调 ±1 / ±12 半音（菜单里四项） |

多个片段共享一条时间轴时，只有**焦点片段**可写，同轨其它片段以 ghost 形式只读显示，
方便对齐。

### 曲线编辑器

| 操作 | 结果 |
| :--- | :--- |
| 点击空白 | 加锚点 |
| 拖锚点 | 移动 |
| 右键 | 删除该处锚点 |
| 工具 `Line` / `Draw` / `Curve` | 折线（直线段）/ 徒手画（自动切成直线）/ 平滑（单调三次） |

曲线值域是归一化的 `[-1, 1]`，与目标参数无关；轴标注显示换算后的真实单位
（例如 `20…18000 Log`）。换成别的目标参数，曲线的形状不变。

## Patch 接线板

节点图。滚轮缩放，中键拖拽平移，框选多选，`Delete` 删除选中节点或连线。

添加节点：空白处右键或 `Shift+A`。

| 菜单项 | 产生 |
| :--- | :--- |
| `Search Nodes…` | 打开节点浏览器，可搜名字或模块路径 |
| `Instrument…` | 乐器：`Synth`（内置）、`SoundFont`、`Sample`、`Drum Kit`、`Mallet`（模态敲击）、`Pluck`（拨弦）、`Organ`（拉杆风琴）、`Wavetable`（波表），以及 CLAP / VST3 乐器插件 |
| `Effect…` | 效果：`Delay`、`EQ`、`Compressor`、`Reverb`、`Chorus`、`Flanger`、`Bitcrusher`、`Phaser`、`Saturation`、`Limiter`、`Ring Mod`、`Vocoder`，以及 CLAP / VST3 效果插件 |
| `MIDI FX…` | `Arpeggiator`、`Portamento`、`MIDI Envelope`、`LFO`、`Curve Map` |
| `Mixer` | 多通道求和节点（1–32 通道，可加 / 减通道） |
| `Keyboard In (computer)` | 电脑键盘输入节点，一个源只允许一个节点；节点上的音条可直接点击试听（`G(octave)..G(octave+2)`，默认 `G3..G5`），`Oct -/Oct +` 改音区、`Tr -/Tr +` 移调，两者都存盘并影响该节点发出的音符；音区同时决定电脑键盘从哪个音开始（窗口的 C），电脑键盘按下时音条上对应的键会亮 |
| `Audio Input (microphone)` | 实时输入节点，带设备选择和电平表 |
| `Feedback Tap` | 反馈抽头：把输入晚一个块求和，让环路合法 |
| `Rescan Plug-ins` | 重新扫描插件 |

`SoundFont` / `Sample` / `Drum Kit` 出生时不带文件（沉默），在节点上的 `Load File…` /
`Load Samples…` 按钮里选，换文件不需要重建节点和连线。

`Mallet`（模态敲击）、`Pluck`（拨弦）、`Organ`（拉杆风琴）和 `Wavetable`（波表）都没有
文件，出生即可发声：DSP 全在引擎里，见下面的 [模态打击](#模态打击mallet)、
[拨弦](#拨弦pluck)、[拉杆风琴](#拉杆风琴organ) 与 [波表合成](#波表合成wavetable)。

三种连线，从输出口拖到输入口即可：

| 线 | 从 | 到 |
| :--- | :--- | :--- |
| MIDI | `Timeline` 的轨道口（`T1`…）或 `Keyboard In` / MIDI FX 输出 | 乐器节点的 MIDI 输入 |
| Audio | 乐器 / 效果的音频输出 | 效果输入（双口效果器分 `Main` / `Mod`，见下）、`Mixer` 通道、`Master` |
| Automation | `Timeline` 的曲线口（`C1`…）或控制源输出（`LFO`、`MIDI Envelope`、`Portamento`） | 节点端口——松手后弹出参数表，选一个目标 |

`Ctrl` + 右键拖拽 = 划断连线。点连线中点会弹菜单，可以把效果直接插进这条线，或删掉它。

端口旁的名字：`Timeline` 节点每个输出口显示它那条轨道的**当前名字**（没改名时显示
`T1` / `C1` / `A1`），`Mixer` 节点每个输入口显示通道名——自定义通道名优先，否则取
接入这一通道的轨道名，再否则是 `Ch N`。名字每帧从工程读取，所以编曲视图里改名后这里
立刻跟着变。超过 6 个全角宽度（约 6 个汉字 / 12 个字母）会截断并显示 `…`，节点不会
因此被撑宽；鼠标悬停可看全名。**右键名字就地改名**：`Enter` 确认、`Esc` 取消，通道名
清空后回落到派生标签。右键落在名字上走改名，落在空白处才是添加节点菜单；左键落在名字
上是选中 / 拖动**节点**本身（名字紧贴插口，也不会误拽出一条连线）。

### 双输入效果器（Main / Mod）

`Ring Mod`、`Compressor` 和 `Vocoder` 有两个音频输入口。节点左侧会画两个插口并标
`Main`（上）和 `Mod`（下）：

| 效果器 | `Main` 接什么 | `Mod` 接什么 |
| :--- | :--- | :--- |
| `Ring Mod` | 主信号（载波 / 被处理的声音） | 调制信号，逐样本与 `Main` 相乘；`mix` 控制干湿比，`mix = 0` 时逐样本直通 |
| `Compressor` | 要被压缩的声部（例如 bass） | **键控源**（例如 kick，需打开 `sidechain`）。压缩量由 `Mod` 的电平决定，与 `Main` 自己的电平无关 |
| `Vocoder` | **载波**：合成器、噪音、任何有谐波的声音 | **调制源**：人声 / 节奏，它的频谱包络被套到载波上 |

`Compressor` 的 `sidechain` 开关默认**关闭**（在 Inspector 最下方）：

- **关闭**：用 `Main` 自己检测，`Mod` 口的线被完全忽略，行为就是普通压缩器。
  接好键控源之后再把开关打开。
- **打开**：只读 `Mod` 口检测。没接 `Mod` 线、或键控源当前安静时，压缩器**不压缩**，
  `Main` 原样通过——这是侧链压缩的正确行为（kick 不打的时候 bass 不该被压），
  不是节点坏了。`stereo_link` 只在关闭时生效（外部键控恒为单一探测器，左右输出同步压缩）。

**Mod 源不要再接 `Master`。** 悬空节点照常运行，但输出没人消费就等于静音，
所以调制源 / 键控源只需要拉一根线到 `Mod` 口；如果顺手也接到 `Master` 或 `Mixer`，
那份原始信号会原样漏进主输出（键控源是 kick 时，你会额外听到一轨 kick）。
同理，`Mod` 口没接线时调制信号视为全零：`mix > 0` 的 `Ring Mod` 输出静音，
开了 `sidechain` 的 `Compressor` 不压缩——两者都是预期行为，不是断线。

每个口最多接一根线；往已占用的口再拉一根会替换旧线。删除双口节点时它
触及的音频线会**一起移除**，不会自动旁路重连（Mod 线没有可解释的主信号替代目标）；
例外是只接了 `Main` 口的 `Compressor`——它删除时和普通单口效果器一样旁路重连。

### Vocoder

`Vocoder` 是 16 带的分析 / 合成滤波器组：`Mod` 口的频谱包络被逐带套到 `Main` 口的
载波上。**接线方向很重要**——`Main` 是载波（合成器、噪音），`Mod` 是人声：

```
instr（载波，例如锯齿波） ──► Main ┐
                                   ├─► Vocoder ──► Mixer / Master
instr（人声 / 鼓）      ──► Mod  ┘
```

`Mod` 口没接就等于包络全零，输出**静音**——不会退化成「用 `Main` 自己分析自己」。

参数：

| 参数 | 范围 | 说明 |
| :--- | :--- | :--- |
| `attack` | 0.5–100 ms | 包络上升速度，短 = 咬字硬，长 = 模糊 |
| `release` | 5–500 ms | 包络下落速度，长 = 尾音拖、糊 |
| `q` | 0.7–16 | 每带的尖锐度。高 = 更「机器人」、带缝更明显；它**只改选择性**，不改响度 |
| `low` / `high` | 40 Hz–1 kHz / 1 kHz–16 kHz | 最低 / 最高带的中心频率，中间 14 个按对数均分 |
| `sibilance` | 0–1 | 带组之上的噪声激励量。人声的齿音 / 气声靠它，`0` 时辅音会发闷 |
| `mix` | 0–1 | 干湿比，`0` 逐样本直通 |
| `output` | −24..+12 dB | 只作用于湿声 |

电平：两个满幅正弦（同频、落在带中心）大约 −4 dBFS，而白噪载波会明显更小 ——
所以先调 `output` 再调 `q`。左右声道的包络与滤波器状态各自独立，参数共用。
vocoder 是当前最重的内置效果（每帧 64 个二阶滤波器），长 release + 高 `q` 也不例外；
它没有延迟，不参与延迟补偿。

### 模态打击（Mallet）

`Mallet` 是一组二阶谐振器被一次噪声敲击激励出来的声音（和 STK ModalBar / LMMS
Mallets 同一路线），一个引擎覆盖四个预设：

| preset | 听感 | T60 |
| :--- | :--- | :--- |
| `Mallet` | 木琴 / 马林巴，近谐波、短促 | 1.2 s（基频） |
| `Vibraphone` | 金属棒，带电机式拍频 | 6 s |
| `Bell` | 钟 / 管钟，非谐波、偏暗 | 14 s（最低模态） |
| `Singing Bowl` | 诵钵，极长尾音、强拍频 | 26 s |

**敲是敲，不是弓**：`note-on` 敲一下，松键**不会**掐断尾音——敲击乐物理上就是响到底。
要立刻收掉所有尾音用 `Stop` / Panic（走 `Off{0}` 哨兵，10 ms 淡出）。

池子 16 个声部。长尾预设（诵钵单音就有 26 s）连续敲会占满池子，第 17 击偷最老的声部：
**保留谐振器状态、只把系数重算到新音高**，所以尾音会滑过去而不是被清零，不会 click。

参数（Inspector 的 modal 分区，画布节点上另有 `decay` / `bright` 两行内联）：

| 参数 | 范围 | 说明 |
| :--- | :--- | :--- |
| `preset` | 四选一 | 换表**不重置**正在响的尾音，它们会滑到新的模态比 |
| `decay` | 0.25–4 | 所有模态 T60 的倍率，实时作用于正在响的尾音 |
| `beating` | 0–2 | 预设拍频的倍率，`0` = 每模态只留一个谐振器（拍频消失） |
| `hardness` | 0–1 | 敲击脉冲长度，**只影响下一次敲击** |
| `brightness` | 0–1 | 敲击噪声的低通截止，**只影响下一次敲击** |
| `gain` | 0–2 | 节点输出增益 |

音高按 MIDI 音符换算（A4 = 440 Hz）。高音区里超过 Nyquist 的高次模态会被丢弃，音色
自然变闷而不是混叠。`decay` / `beating` / `hardness` / `brightness` / `gain` 都能接
自动化曲线，`preset` 是离散值、不进自动化列表。

### 拨弦（Pluck）

`Pluck` 是 Karplus-Strong 拨弦：一根延迟线（弦长决定音高）+ 一个环路低通（阻尼）+
一圈噪声（拨的那一下）。音色是**严格谐波**的，和 `Mallet` 的非谐波金属感互补：

| 参数 | 范围 | 说明 |
| :--- | :--- | :--- |
| `decay` | 0.1–20 s | 基频的 T60，实时作用于正在响的弦 |
| `damping` | 0–1 | 环路低通截止 `f0 · 2^(2+3(1−damping))`，越大越闷，实时生效 |
| `brightness` | 0–1 | 激励噪声的亮度，**只影响下一次拨弦** |
| `release` | 0.005–2 s | 松键后弦被闷掉的时间（T60），**只影响下一次松键** |
| `gain` | 0–2 | 节点输出增益 |

**和 `Mallet` 相反：松键会闷弦。** 拨弦乐器唯一的「止音」手段就是抬起手指，所以
`note-off` 会按 `release` 把弦闷掉；`Mallet` 则响到底。要立刻收掉所有尾音用
`Stop` / Panic（`Off{0}` 哨兵，10 ms 淡出）。

两点容易误判：

- **第一个周期是静音**。激励要走完一圈才到输出，A4 约 2.3 ms 听不出来，但 MIDI 0
  （约 8 Hz）要 122 ms——低音区会觉得「起音晚了一点」，这是算法本身，不是坏了。
- **`damping` 很重时尾音比 `decay` 短**。阻尼吃掉的能量无法靠增益补回来（增益有
  0.99995 的硬上限，再高就自激了）。想让长尾拖住就把 `damping` 往下拧。

池子 16 个声部，第 17 个音偷最老声部：**保留环里的振动、只把弦长重算到新音高**，
尾音滑过去而不是被清零。同音重拨 = 在还在响的弦上再拨一下，两次激励叠加。

`decay` / `damping` / `brightness` / `release` / `gain` 五个都能接自动化曲线
（画布节点上另有 `decay` / `damp` 两行内联）。

### 拉杆风琴（Organ）

`Organ` 是音轮风琴的加法合成：**九根 drawbar 就是九个严格谐波的正弦**，同时发声、各自
独立电平。音色完全由「哪几根拉出来」决定，中间没有滤波器——这就是拉杆风琴和 `Synth`
的根本区别（`Synth` 是一个振荡器过一个滤波器，这里是九个振荡器并联直出）。

| # | drawbar | 音程 | 相位倍数 | 音色作用 |
| :-- | :-- | :-- | :-- | :-- |
| 0 | `16'` | 低八度 | 1 | 底噪层，给和弦垫脚 |
| 1 | `5⅓'` | 16' 的三次谐波 | 3 | 偏「爵士」的厚重感 |
| 2 | `8'` | 同度 | 2 | 主体，几乎所有注册都开 |
| 3 | `4'` | 八度 | 4 | 明亮度 |
| 4 | `2⅔'` | 三次谐波 | 6 | 中空的「鼻音」 |
| 5 | `2'` | 两个八度 | 8 | 穿透力 |
| 6 | `1⅗'` | 五次谐波 | 10 | 金属光 |
| 7 | `1⅓'` | 六次谐波 | 12 | 尖 |
| 8 | `1'` | 三个八度 | 16 | 最尖，独奏时用 |

每根 0–8 级，**3 dB/级**：`8` = 1.0、`4` = 0.251、`1` = 0.089、`0` = 关断。默认注册
`888000000`（16' / 5⅓' / 8'），也是真机最常见的「全下」音色。

九根拉杆的顺序是按 footage 排的，不是按谐波序号——`5⅓'` 排在 `8'` 前面是因为它更低。

参数（Inspector 的 organ 分区，画布节点上另有 `8'` / `perc` 两行内联）：

| 参数 | 范围 | 说明 |
| :--- | :--- | :--- |
| `16'` … `1'` | 每根 0–8 级 | 逐根电平（3 dB/级），**实时作用于正在响的和弦**——拉杆就是演奏动作 |
| `perc` | 0–1 | 打击泛音电平，`0` = 关 |
| `perc decay` | 0.1–2 s | 打击泛音的 T60 |
| `perc harmonic` | 2nd / 3rd | 打击泛音取 `4'`（2nd）还是 `2⅔'`（3rd） |
| `attack` | 1–200 ms | 起音斜坡，防止每个音头 click |
| `release` | 5 ms–1 s | 松键斜坡 |
| `gain` | 0–2 | 节点输出增益 |

**打击泛音（percussion）** 是音轮风琴攻击性的来源：一下键就额外叠一根 `4'` 或 `2⅔'`
的正弦，按 `perc decay` 指数衰减到没。它加在总包络**之前**，所以松键时一起被关掉——这是
真机行为。和真机的一处差异：真机在按住别的键时不会再触发打击（single-trigger），这里
**每次按键都触发**，所以弹和弦时打击更厚。

**力度不起作用**，这是刻意复刻真机：音轮风琴的键触点就是个开关，只有按下和松开。想要
力度动态请换 `Mallet` 或 `Pluck`。响度靠注册 + `gain`。

**滑音不内置，但白拿**：`PitchOffset` 是逐样本平滑的，接一个 `Portamento` MIDI FX 就得到
滑音，还附带 `legato_only` / `min` / `max` 三个开关。风琴本身不做 glide。

三点容易误判：

- **高音区音色会变薄**。超过 Nyquist 的 drawbar 被丢掉（而不是折回低八度 foldback），
  所以越往高音弹，上方那几根越听不见。这是刻意的：foldback 会让「注册决定音色」这个
  直觉失效。
- **把所有拉杆推回 0 才是静音**。留一根在 1 级也仍然发声（−21 dB），这也是真机行为。
- **同音重按不会更响**。同一个键按两次是复用同一个声部、从当前电平重新起音，不是叠加
  两个声部。这一点和 `Pluck` 的重拨不同（拨弦重拨是真叠加）。

池子 16 个声部，第 17 个音偷最老声部（从当前电平淡出、重触发打击，不会 click）。
九根 drawbar + `perc` / `perc decay` / `attack` / `release` / `gain` 都能接自动化曲线，
`perc harmonic` 是离散值、不进自动化列表。九个 drawbar 全在自动化菜单里是按设计来的：
**拉杆扫动本身就是风琴最标志性的演奏动作**。

### 波表合成（Wavetable）

`Wavetable` 是这组声源里唯一「有数据」的一个。它内置四张单周期波形表，`position` 在你的
演奏下在相邻两张之间做插值——**同一时刻只有一条波形**，不是四个振荡器相加。这是它和
`Organ` 的根本区别：

| | `Organ` | `Wavetable` |
| :--- | :--- | :--- |
| 谐波从哪来 | 九根 drawbar 实时算正弦 | 烘焙在表里 |
| 谐波数量 | 九根，固定 | 最多 256 次，随音高变化 |
| 改变音色 | 推拉某几根 bar | 扫 `position`，整条波形连续变形 |
| CPU | 每根 bar 一次 `sin` | 一次查表 + 插值，**与谐波数无关** |

四张表就是 `position` 的四个落点：

| `position` | 波形 | 谐波成分 |
| :--- | :--- | :--- |
| `0.00` | 正弦 | 只有基频，最干净 |
| `0.33` | 三角 | 奇次谐波，幅度按 `1/k²` 快速衰减，圆润 |
| `0.67` | 锯齿 | 全部谐波，按 `1/k` 衰减，最「亮」 |
| `1.00` | 方波 | 只有奇次，按 `1/k` 衰减，空心 |

中间位置是相邻两张表**逐样本线性插值**的结果，所以从 `0` 慢慢推到 `1` 是一个连续的变形，
不是四个档位跳变。

参数（Inspector 的 wavetable 分区，画布节点上另有 `pos` 一行内联）：

| 参数 | 范围 | 说明 |
| :--- | :--- | :--- |
| `position` | 0–1 | 在四张表之间插值，**实时作用于正在响的音** |
| `attack` | 1 ms–2 s | 起音斜坡 |
| `release` | 5 ms–5 s | 松键斜坡（合成器可以拖很长） |
| `gain` | 0–2 | 节点输出增益 |

Inspector 里那条小波形是你**当前 `position` 下的一个周期**，扫滑杆时会实时重画——想知道
`0.5` 听起来长什么样，看它比听它快。

**高音区会自动丢谐波。** 一张表的谐波数原本是固定的，音越高，高次谐波越容易越过
Nyquist 折回成不合谐的杂音（混叠）。所以引擎为每张表预生成了九层「带限」版本
（256 / 128 / 64 / … / 1 次谐波），按音高选层。结果是：低音保留全部 256 次谐波，越往上
谐波越少、音色越薄，但**永远不会有混叠杂音**。这是刻意的取舍，也是所有波表合成器的做法。

三点容易误判：

- **力度是真的有作用的**，与 `Organ` 相反：`velocity` 直接决定这个音的电平（0.5 的力度约
  是一半音量）。想要力度不敏感的键盘音色用 `Organ`。
- **扫 `position` 不会改变音量**。四张表各自按峰值归一化，响度靠 `gain` 与 Master。所以
  「换个位置听不出音量变化」是对的，不是坏了。
- **高音区不是「坏了」**，是谐波被合法地丢掉了。想在高音区也要亮，接一个 EQ 往上提，或
  干脆用 `Organ`（它的 drawbar 是各自判 Nyquist 的，不会整体变薄）。

池子 16 个声部，第 17 个音偷最老声部。`position` / `attack` / `release` / `gain` 都能接
自动化曲线——**扫 `position` 就是这个乐器最标志性的演奏动作**，和风琴的拉杆扫动一个地位。
滑音同样白拿：`PitchOffset` 逐样本平滑，接 `Portamento` 即可。

这一版**不支持导入自己的波形文件**（`.wav` / `.wt`），也不带滤波器与 unison：音色完全由
`position` 决定。要更有个性的音色，接既有 EQ 或后续的 Filter。

双击节点进 `Inspector`（乐器 / 效果 / 混音 / MIDI FX / LFO / Curve Map / Audio Input）；
双击固定的 `Timeline` 节点回到编曲视图。

## Inspector 与混音

`Inspector` 显示当前节点：

| 节点 | 面板内容 |
| :--- | :--- |
| 乐器 | 内置合成器的波形与滤波（Low-pass / High-pass / Band-pass / Moog 四级 ladder）、ADSR、滑音；`SoundFont` 的 bank / patch 与文件；`Sample` 的根音、增益，以及**播放窗口**（波形图上四条可拖标记：起始 / 循环起 / 循环止 / 结束，外加循环模式 Off / Forward / Ping-pong）；`Drum Kit` 的每个槽位（触发键写作 `C2 · 36`，可直接拖动换键）；`Mallet` 的预设下拉与 decay / beating / hardness / brightness / gain；`Pluck` 的 decay / damping / brightness / release / gain；`Organ` 的 3×3 drawbar 网格（每根 0–8 级）、打击泛音（电平 / 衰减 / 2nd·3rd）与 attack / release / gain；`Wavetable` 的 `position` 滑杆 + **一个周期的波形预览** + attack / release / gain |
| 效果 | 该效果的全部参数；插件效果用插件自己的 GUI（`Open Editor`） |
| `Mixer` | 通道条：每路推子、声像、静音、独奏、电平表，加 / 减通道；输出级的声像与静音 |
| 插件乐器 | 参数列表（可右键接到自动化）+ `Open Editor` |
| `Audio Input` | 设备选择、通道电平表 |

`Mixer` 通道条顶部的通道名可以**右键就地改名**（`Enter` 确认、`Esc` 取消，清空回落到
默认的 `Ch N · 轨道名`）。整格都是点击目标，直接右键名字本身即可；改名只记一步 undo，
且与 `Patch` 视图里输入口旁显示的名字保持一致。

`Master` 推子和电平表在走带栏右侧，属于整首歌，不在 Inspector 里。

## 自动化

两条路：

1. **曲线轨**：`+ Curve` 加一条控制轨，在 `Patch` 里从它的 `C1` 口拖一条 automation 线到
   目标节点，松手时选参数（节点参数、`CC` 预设、pitch bend、tempo 都在列表里）。
   然后在时间轴双击曲线片段，进 `Edit` 画点。
2. **控制源节点**：`LFO` / `MIDI Envelope` / `Portamento` 的 control 输出拖到目标参数，
   发的是实时控制流，不需要画曲线。

改目标参数不会破坏曲线形状（曲线存归一化值，轴在连线上）。tempo 也可以被曲线驱动：
走带栏的 BPM 框右侧会显示 `→ 128.0 auto`，表示时钟正被 `Timeline In` 的曲线接管。

## 插件

支持 CLAP 和 VST3 的乐器与效果。启动时扫描一次并缓存，装 / 删插件后用
`Patch` 右键 → `Rescan Plug-ins`。

搜索路径（先环境变量，再标准目录）：

| 格式 | 环境变量 | 标准目录（Windows） |
| :--- | :--- | :--- |
| CLAP | `GLITCHERZ_CLAP_PATH` | `%ProgramFiles%\Common Files\CLAP`、`%LOCALAPPDATA%\Programs\Common\CLAP`、`%LOCALAPPDATA%\CLAP`、`%APPDATA%\CLAP` |
| VST3 | `GLITCHERZ_VST3_PATH` | `%ProgramFiles%\Common Files\VST3`、`%LOCALAPPDATA%\Programs\Common\VST3`、`%APPDATA%\VST3` |

环境变量用系统路径分隔符（Windows 是 `;`）列多个目录。目录内不递归，只扫一层
（VST3 的 bundle 目录算一个条目）。

插件的参数值与完整状态（插件自己序列化的 state）随工程保存，重开工程会回灌。
单个插件保存状态失败只记日志，不会让整次保存失败。

## 录音

录音前要先让轨道"布防"：时间轴每条轨都有一个输入口，只有接上源才会录。

| 类型 | 接法 |
| :--- | :--- |
| MIDI | `Patch` 里把 `Keyboard In`（或某个 MIDI FX）的 MIDI 输出拖到目标轨的 `T1` 口 |
| 音频 | 把 `Audio Input` 节点的音频输出拖到音频轨的 `A1` 口 |

走带栏的 `⏺` 或按 `R` 开始。录制设置：

| 控件 | 作用 |
| :--- | :--- |
| `0 bar` 输入框 | 预备拍 0–2 小节，这段不计入录音 |
| `Mute others` | 录音时静音其它 MIDI 轨的已排音符 |
| `0 smp` 输入框 | 手动输入延迟补偿（样数），正值把音频片段往前挪；仅本次会话有效，不存进工程 |

录音中再按一次 `R` 或 `Space` 是 punch out（收尾但继续播放），`⏹` 收尾并回到开头。

音频 take 写进 `<工程名>.media/`，文件名 `rec-<时间戳>-a<轨号>.wav`，所以**必须先保存工程**
才能录音频——未命名工程会提示先存盘。

## 导出

### 音频

`File ▸ Export Audio…`：

| 选项 | 说明 |
| :--- | :--- |
| `Full song` | 从 0 到编曲末尾 |
| `Song loop` | 只导标尺上启用中的 loop 范围（没画时禁用） |
| `Depth` | `16-bit` / `24-bit`（默认）/ `32-bit float` |
| `Rate` | 设备当前采样率 + 44.1 / 48 / 88.2 / 96 kHz |
| `Also write stems` | 混音之后再逐轨渲染，一轨一个文件 |

- 立体声 wav，末尾多渲 1 秒让延迟与混响尾巴收干净。
- 导出用离线引擎，选 96 kHz 不需要 96 kHz 硬件；音频片段按时长播放，换采样率不变调。
- stems 的命名是 `<混音文件名>_<轨名>.wav`（未命名轨是 `MIDI 1` / `Audio 1`），重名追加
  ` 2`、` 3`；非法字符换成 `_`。stem 里保留自动化与 tempo 曲线——那是"这条轨听起来的样子"。
- 导出期间编辑文档不影响这次渲染（开始时已快照）。一次只允许一个导出任务。
- 取消会删掉当前那个没写完的文件，已完成的 pass 保留。

#### 命令行渲染

`glitcherz --render <工程.glz> <输出.wav>` 不开窗口、不打开音频设备，直接在后台把工程渲成
立体声 wav，适合批量导出、CI 和脚本。可选参数：`--rate <Hz>`（默认 44100）、
`--bits 16|24|32f`（默认 24）、`--to <tick>`（截止位置，默认整曲）。

```bash
glitcherz --render song.glz song.wav --rate 48000 --bits 16 --to 7680
```

它和窗口里的 `Export Audio…` **共用同一套离线装配**，所以同样的工程、同样的采样率与位深会
得到逐样本一致的声音。差别只在交互：命令行只出单个混音文件，没有 stems、song loop 范围和进度条；
工程里的相对媒体路径仍然相对工程文件所在目录解析。

#### 命令行：批量命令

`--ops` 与 `--do` 让脚本（或 AI agent）在无窗口状态下**改**工程，而不只是把它转成 wav。
命令来自窗口里 `Edit ▸ …` / `Event ▸ MIDI Operations` 用的**同一张注册表**——同一个 id、同一套参数、
同一份撤销语义，命令行没有任何「隐藏版」。

先看看有哪些命令：

```bash
glitcherz --commands                    # 一行一条：id、名称、参数
glitcherz --commands --json | jq .      # 再加 menu / 快捷键 / 为什么现在不可用
```

然后按顺序跑一批：

```bash
glitcherz --open song.glz \
  --do midi.transpose --params '{"track": 0, "clip": 0, "semitones": 12}' \
  --do midi.quantize  --params '{"track": 0, "clip": 0, "grid_ticks": 240, "strength": 0.8}' \
  --save song-up.glz --wav song-up.wav
```

命令多了就写进文件，避免命令行里的引号地狱：

```bash
glitcherz --open song.glz --ops steps.json --save out.glz
```

`steps.json` 就是一个数组，`params` 可以省（等同 `{}`）：

```json
[
  { "id": "midi.transpose", "params": { "track": 0, "clip": 0, "semitones": -12 } },
  { "id": "midi.velocity_op", "params": { "track": 0, "clip": 0, "op": "humanize", "value": 15 } },
  { "id": "midi.query", "params": { "track": 0, "clip": 0 } }
]
```

`--ops -` 从标准输入读，效果与文件一样。`--ops` 与 `--do` 可以混用，
**按它们在命令行里出现的顺序执行**（`--do a --ops list.json --do b` 就是 `a, list…, b`）。

| 参数 | 说明 |
| :--- | :--- |
| `--open <工程.glz>` | 起始工程。不给就从**新建工程**开始 |
| `--ops <file\|->` | 读一个 JSON 数组，`-` 表示标准输入 |
| `--do <id>` | 追加一条命令；紧跟其后的 `--params` 给它参数 |
| `--save <out.glz>` | 全部命令成功后写盘 |
| `--wav <out.wav>` | 全部命令成功后渲染（可用 `--rate` / `--bits` / `--to`） |
| `--json` | 把结果输出成单个 JSON 对象，供程序消费 |

四点值得先知道：

- **批次是全或无的。** 任何一条命令失败，整批立即停止，`--save` 与 `--wav` 都不写——不会留下半个
  改过的工程。想要「跳过坏的继续」，就把批次拆成几次调用。
- **`--wav` 渲染的是刚改完的样子**，不是磁盘上那份旧文件。所以「改一版 → 听一版」一次调用就够。
- **`--save` 沿用窗口里的保存语义**：先写 `.glz.tmp` 再改名，并把被替换的那一版留成 `.glz.bak`。
  反复覆盖同一份文件会让 `.bak` 跟着翻滚，批量脚本最好每次写新文件。
- **新建工程里没有 clip**，而全部 `midi.*` 命令都作用于已有的 clip。所以从零开始编曲仍要先准备一份
  模板工程（窗口里存一份带 clip 的空工程即可）。

`--json` 输出的信封长这样（`saved` / `render` / `failed` 只在对应情况发生时出现）：

```json
{
  "ok": true,
  "project": "song.glz",
  "commands": [ { "id": "midi.transpose", "ok": true, "result": { "transposed": 4 } } ],
  "saved": "out.glz",
  "render": { "path": "out.wav", "frames": 44288, "sample_rate": 22050 }
}
```

失败时 `ok` 为 `false`，`failed` 里带 `stage`（`ops` / `load` / `command` / `save` / `render`）；
`stage` 是 `command` 时还有 `id` 和 `kind`（`unknown` 写错了 id、`unavailable` 这条命令现在不适用、
`bad_params` 参数不对、`panicked` 命令内部崩了但已回滚）。

#### 命令行：MCP server

`glitcherz --mcp` 把上面那套命令面**当成 MCP 工具**开放给 AI 客户端（Claude Desktop、
各种 agent 框架）。协议跑在 stdin/stdout 上，一行一个 JSON 对象，不需要端口、不需要网络。

```bash
glitcherz --mcp --root ~/Music/glitcherz
```

客户端那边加一条 stdio server 即可：

```json
{
  "mcpServers": {
    "glitcherz": {
      "command": "glitcherz",
      "args": ["--mcp", "--root", "/Users/me/Music/glitcherz"]
    }
  }
}
```

六个工具：

| 工具 | 做什么 |
| :--- | :--- |
| `project_open` | 打开一份 `.glz`，返回摘要（轨道 / 片段 / 音符数 / 时长 / 有多少节点用插件） |
| `project_save` | 存盘（原子写 + `.bak`）；不给路径就存回原文件 |
| `project_info` | 只读摘要，字段与 `project_open` 一样 |
| `commands_list` | 枚举命令（与 `--commands --json` 同一份），含「现在为什么不可用」 |
| `commands_run` | 按顺序跑一批命令，可 `dry_run`（跑完自动回滚） |
| `render_wav` | 把**当前内存里的文档**渲成立体声 wav |

三条边界，全都默认收紧：

- **只能在 `--root` 里读写。** 客户端给的每个路径都先相对 root 解析，再判越界；绝对路径也照样判。
  越界不会「尽力而为」，直接报 `stage: "path"`。
- **插件默认不加载。** CLAP / VST3 是 `dlopen` 任意二进制，而 MCP 那头的参数是模型拼的。所以在
  MCP 模式下，插件乐器渲染成静音、插件效果器回落成内置效果，`render_wav` 的 `warnings` 会逐节点
  说明是哪几个。确实要用就显式加 `--allow-plugins`。
- **没有 undo / redo 工具。** 改坏了重开一次工程。`commands_run` 的 `dry_run` 是先验证再落地的那条路。

和 CLI 的一处重要差别：**批次不是全或无**。`commands_run` 里每条命令各自原子（要么完整生效要么
完全不生效），但第 3 条失败时前 2 条已经改了文档——会话是活的，没有「先攒着最后一起提交」这回事。
默认 `stop_on_error: true`，失败即停，报告里把剩下的列进 `skipped`。

一次典型的来回（`tools/call` 的 `content[0].text` 是一个 JSON 字符串，这里摊开展示）：

```text
→ {"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"commands_run","arguments":{
     "commands":[{"id":"midi.transpose","params":{"track":0,"clip":0,"semitones":12}}]}}}
← {"id":1,"result":{"isError":false,"content":[{"type":"text","text":
     "{\"ok\":true,\"applied\":true,\"results\":[{\"id\":\"midi.transpose\",\"ok\":true,…}],\"skipped\":[]}"}]}}
```

`--mcp` 的退出码：`0` 对端关闭 stdin、`1` stdout 写不出去、`2` 参数错（`--root` 不存在、
与 `--render` / `--ops` 混用）、`3` `--open` 预载的工程读不了。工具自身失败**不**影响退出码。

#### 退出码

`glitcherz` 的所有模式共用一套退出码，脚本可以据此分支：

| 码 | 含义 |
| :--- | :--- |
| `0` | 成功 |
| `1` | 音频引擎或窗口启动失败（仅开窗口时） |
| `2` | 参数或输入文档有问题（未知开关、`--params` 不是 JSON 对象、`--ops` 读不到或不是数组、`--render` 与批次混用、`--mcp` 的 `--root` 不存在或与其它模式混用） |
| `3` | 工程文件读写/解析失败，或渲染失败（`--mcp --open` 预载失败也是 `3`） |
| `4` | 某条命令执行失败 |

注意：`--render` 失败以前一律返回 `1`，现在归到 `3`（与批次共用）。靠退出码区分「工程读不了」和
「渲染失败」的话，两种都落在 `3`，具体原因看 stderr。

`File ▸ Export MIDI…` 把 MIDI 轨写成标准 MIDI 文件（SMF）。

## 偏好设置

`Edit ▸ Preferences…`：

| 项 | 说明 |
| :--- | :--- |
| `Device` | 输出设备，`System default` 是跟随系统 |
| `Sample rate` | 设备默认，或 44.1 / 48 / 88.2 / 96 / 176.4 / 192 kHz |
| `Buffer size` | 输出缓冲（样数），越小延迟越低、越容易爆音 |

改完点 `Apply`：先建新引擎，成功才替换并重建整张图；失败保留旧引擎并在窗口里报错。
插拔设备后点 `Refresh devices` 重新枚举。配置存在应用数据目录，下次启动自动套用，
设备不在就回落默认并提示。
